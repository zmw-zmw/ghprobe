# 运营商按「境外连接」针对你？自救三件套

> 适用场景：因为「连接境外服务器较多」，运营商对你**限速 + SNI 阻断**，连 DoH 的 TLS 握手都被 reset。
> ghprobe 全程**没有代理/隧道/流量转发** —— 所有手段都不绕过任何封锁，只是「不被额外打扰」。

## 先划边界

如果运营商升级到「国际总流量 QoS」或对 github.com 本体全量 SNI 封锁，**不使用代理的工具无法对抗**
（raw 这类被精确 RST 的域名只能走兜底镜像）。这是架构边界，不是努力问题。
以下三件套解决的是：在链路本身可达的前提下，把「被画像、被针对」的面积压到最小。

## ① 无 SNI DoH：DNS 层对 SNI 阻断免疫

SNI 阻断掐的是 TLS ClientHello 里的明文主机名。但实测这些公共 DoH 端点的证书**自带 IP SAN**：

| 端点 | 无 SNI 直连（证书按 IP SAN 校验） |
|---|---|
| 223.5.5.5 / 223.6.6.6（阿里） | ✅ |
| 1.12.12.12 / 120.53.53.53（DNSPod） | ✅ |
| 221.181.72.233（360） | ✅ |
| 111.7.73.60 / 39.156.84.71（360） | ❌ 证书不含该 IP |

**做法**：把配置里 DoH 端点的 `sni` 字段**删掉**即可（ghprobe 在 sni 缺省时本来就不发 SNI，证书校验照常）：

```yaml
doh:
  - { host: 223.5.5.5, path: /dns-query }
  - { host: 1.12.12.12, path: /dns-query }
```

配合 `dohUdp`（UDP 53 本来就没有 SNI 可掐）—— 候选来源很难被完全掐死。

## ② 轻探活：连接数砍半

`schedule.lightProbe: true`（默认开）—— 健康态只探主条目，备选**按需才测**
（主挂了当轮补测再决策，结果与全量探活完全一致）。运营商画像看的是「境外连接频率」，
这一项直接减半。

## ③ 间隔抖动：打破机器特征

`schedule.jitter: 0.15`（默认 ±15%）—— 「每 90.000 秒准时握手」和「每 90s±13s 自然波动」
在运营商的画像算法里是两种用户。抖动让 ghprobe 的探测看起来就是正常流量。

## 低调模式参考配置（个人化，改自己的 config.yaml）

```yaml
doh:                       # 3 条且无 sni 字段
  - { host: 223.5.5.5, path: /dns-query }
  - { host: 1.12.12.12, path: /dns-query }
  - { host: 221.181.72.233, path: /dns-query }
dohUdp:
  servers: [114.114.114.114, 119.29.29.29]
probe:
  maxCandidates: 4         # 默认 8
  maxPoolIps: 12           # 默认 32
  concurrency: 4           # 默认 10
schedule:
  daemonHealthyMs: 120000  # 默认 90000
proxy:
  idleProbeMin: 10         # 默认 5
```

原则：少连、慢连、乱连（抖动）、DNS 加密且无主机名可掐 —— 把自己从「显眼目标」变回「普通用户」。
